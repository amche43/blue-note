# 自建题库、识别与交流

## 本次已实现的 0.2 功能

用户可以在“学习”或“我的”页面新增题目，填写题干、公式、解答、触发线索、关键动作、使用条件、误用点和来源。解答可以留空，之后再补。题目支持编辑、删除、搜索和私人备份。

“查找相关知识点”会在首批知识库中做关键词匹配，展示参考例题和适用条件，由用户选择是否引用。它没有做自动推导，不应把匹配结果称为可靠的 AI 解题结论。

自建题目的每次修改生成独立修订，删除也作为修订保存。复习状态不会把“新增题目”误算成一次正确作答。没有变式的题目不显示变式练习按钮。

分享前显示将分享的内容范围，要求单独勾选同意，之后才能复制题目包。题目包不包括私人蓝笔笔记、学习进度或同步口令。收件人先预览，再保存成自己的副本；重复导入不会覆盖收件人的编辑。当前这是题目包交换，尚未上传到社区服务器。

## 后续：拍照转成电子题

交互顺序：拍照或选图 → 裁剪一题 → 识别文字和公式 → 对照原图核对 → 保存私人题目 → 查找或整理关键点。

优先评估开源的 [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)，它提供文字、公式及文档结构识别能力。模型的实际效果仍需要用用户自己的印刷题、手写题、积分符号和上下标样本测试。无需先购买商业识题 API；本机模型仍会消耗计算资源。

识别结果保存原图引用、识别文本、用户确认后的文本和对应版本。公式转写与数学推理是两步：识别出“拉格朗日中值定理”不代表已经确认题目满足连续、可导等条件。关键点应给出触发线索与适用条件，并允许用户修改。

本次没有接入相机、相册或 OCR 模型，也不会把粘贴文字功能包装成拍照识别。

## 后续：允许其他用户下载

个人同步和社区共享分别处理。个人同步只给自己账号的设备传题目、笔记与进度；社区发布只上传作者明确选定并确认的一份题目版本。

题目默认 private。发布前预览题面、解析、关键点与署名，明确同意后提交；公开页展示作者、修订版本和来源。作者修改私人草稿不自动改动已经公开的版本。

其他用户点击下载后，获得自己的可编辑副本，保留作者署名与原始版本关联。作者可以撤回公开入口；已经被别人下载的副本无法保证远程删除，发布页面应说明这一点。

正式服务需要独立用户身份和服务端所属权检查。现有“一个个人口令对应一份日志”的 Java 服务不能直接当成公共社区账号系统。后续采用 Java 服务配数据库，并把图片文件单独存储；客户端继续共用同一套 Flutter 代码和 HTTPS 接口，为 iOS 保持互通。

建议的数据实体：用户、题目、题目修订、公开发布记录、下载来源关联、评论、点赞。发布记录保存用户的确认时间及具体修订编号；服务端根据真实登录身份判定谁能发布、修改或撤回。

## 后续：讨论与点赞

每个公开题目版本有自己的讨论区，支持提问、补充解法和指出错误。评论不直接覆盖作者原题；作者可以根据讨论发布新的修订。

同一用户对同一条内容只有一个点赞状态，可以取消；服务端计算数量，不能让客户端随意提交点赞总数。点赞表示有帮助，不等于答案已经正确。

公共交流需要删除自己的评论、举报不当内容和管理员处理入口。先实现按时间排序与有帮助排序，不把点赞数量当成题目质量的唯一指标。

## 完成标准

1. 自建题库：无解析也能保存、重开可读、备份可恢复、分享不带私人记录。本次已实现并测试。
2. OCR：真实图片与公式样本验收，逐项核对易错符号后才入库。尚未实现。
3. 社区：两个独立账号完成明确授权发布、下载、撤回；账号之间不能改对方私有内容。尚未实现或部署。
4. 交流：评论、删除、点赞取消及重复请求均经过双账号测试。尚未实现。

开发和本机试验可以优先使用免费开源工具。公开服务器、图片存储、带宽和模型计算是否有费用，取决于后续部署方式，当前未购买或开通任何付费服务。
